HVR_OPT final test report -- where it lives

The final test result is not stored in the tracked tree. A tracked report cannot name the
commit that contains it: committing it creates a new SHA whose own state was never tested,
and reporting on that commit would need yet another commit (final brief Part 30). The
earlier reports in this file (last: tested commit 5fa5821) followed that pattern and are
superseded by this policy.

The full suite is run on the exact final pushed commit by

    python scripts/final_closure_test_report.py --note

which refuses a dirty tracked tree or a HEAD that differs from its upstream, runs

    python -m pytest tests -q -p no:cacheprovider --basetemp=$HVR_SCRATCH/pytest_final_tmp \
        --junitxml=$HVR_SCRATCH/pytest_final.xml -rfE

fails if the run modified any tracked file, and attaches the report to the tested commit
as a git note:

    git fetch origin refs/notes/test-reports:refs/notes/test-reports
    git notes --ref=test-reports show <sha>

No CI run is claimed: no workflow is committed (the push credential lacks the 'workflow'
scope); the report is a local run.
